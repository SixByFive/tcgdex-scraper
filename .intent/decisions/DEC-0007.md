## Context

The original `H:/Pricing-ID Tooling` repo and this scraper were growing in parallel and overlapping (both have a Bun web UI, both list sets, both read the cards-database repo). The intended flow is **Scrape → Pricing tooling → Write**, and running it as two separate processes with two separate UIs is friction without benefit: the pricing tooling needs the set to exist in cards-database, which only happens after the scraper's emit step.

## Decision

Absorb the pricing tooling's source into `tcgdex-scraper/src/pricing/`, verbatim (same file names, same relative imports). Carry its `.intent` over (DEC-0001..0004, product-matching, variant-migration, web-ui plans). Expose its orchestrator (`runEnrichment`) through this scraper's CLI (`enrich` command) and UI (an "Enrich" button on the set grid, with the ambiguous-variant mapping panel).

The standalone `H:/Pricing-ID Tooling` repo is deprecated. A `DEPRECATED.md` at its root points at this scraper. The folder is retained until the user deletes it.

## Consequences

- Single tool, single UI, single CLI for the whole scrape → enrich → write pipeline.
- Historical commits for the pricing tooling live in its own repo; ongoing changes happen here.
- Any external consumers (CI, scripts) that invoked `H:/Pricing-ID Tooling`'s CLI need to be repointed at `H:/tcgdex-scraper`'s `enrich` command.
