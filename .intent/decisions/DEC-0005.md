## Context

Each new set has to be scraped from somewhere before enrichment can add marketplace IDs. Alternatives considered:

- **tcgcollector / pokebeach / pokecottage** — EN only, no reliable multi-locale coverage.
- **pokemon.com regional sub-sites** — covers all 7 tcgdex international locales except es-mx (Mexico redirects to a shop, no card DB), and critically the DOM is identical across locales for the structural fields.

## Decision

pokemon.com is the single source for card content. One EN page per card provides the structural fields (types, cost energies, stage, category, HP, rarity, weakness, retreat, illustrator). Structural fields are English-keyed in the DOM — the energy `title` attribute is localised but `data-energy-type` and `icon-<name>` classes stay in English on every locale — so they are safe to read from any page.

Per-locale pages (de, fr, it, es, pt) are fetched only to pull the translated `name`, attack `name`, and attack `effect` text.

es-mx has no pokemon.com instance; it falls back to `es`.

## Consequences

- One scrape = 6 fetches per card (EN + 5 translation locales).
- The scraper can be rerun to update translations without touching structural fields (planned).
- Cards never seen on pokemon.com (very old or Asian-exclusive) cannot be scraped by this tool.
